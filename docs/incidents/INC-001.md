# INC-001 — Inconsistencia en salida del comando `health`

## Identificación

* **Incidente:** INC-001
* **Caso de prueba relacionado:** TC-001
* **Severidad:** Baja
* **Fecha de detección:** 2026-10-03
* **Estado:** Abierto
* **Componente:** Daemon / comando `health`

## Síntomas

Durante la ejecución de **TC-001 — Envío y ejecución de un trabajo**, el caso de prueba terminó en **FAIL** durante la verificación de disponibilidad del daemon.

El comando `health` respondió correctamente y confirmó que el daemon estaba funcionando, pero la cadena obtenida no coincidió con la cadena definida en la validación automática del caso de prueba.

La diferencia corresponde únicamente a la capitalización del nombre del proyecto:

* Esperado por TC-001: `speedyg`
* Observado en la implementación: `speedyG`

## Evidencia

La ejecución del comando:

```bash id="e3q6pz"
cargo run --bin speedyg -- health
```

produjo:

```text id="h8x1va"
OK: Daemon speedyG funcionando correctamente
```

Mientras que TC-001 esperaba:

```text id="p3yq7m"
OK: Daemon speedyg funcionando correctamente
```

Archivos de evidencia:

```text id="b1s7pd"
verif/results/TC-001/health-after-error.txt
verif/results/TC-001/execution.log
```

El resultado general de **TC-001 fue FAIL**.

## Hipótesis

1. La implementación del comando `health` utiliza una capitalización diferente a la definida originalmente en el caso de prueba.
2. El caso de prueba contiene una salida esperada desactualizada respecto a la implementación actual.
3. Existe una falta de definición única de la nomenclatura oficial de `speedyG` en la especificación del sistema.

## Causa

Se identificó una inconsistencia entre la salida implementada por el daemon y la salida esperada por TC-001.

La implementación actualmente devuelve:

```text id="x4j8k2"
OK: Daemon speedyG funcionando correctamente
```

mientras que el caso de prueba valida:

```text id="p9r5tw"
OK: Daemon speedyg funcionando correctamente
```

La causa es, por tanto, una **inconsistencia de nomenclatura entre implementación y verificación**.

## Corrección

Definir una única salida oficial para el comando `health` y actualizar el componente correspondiente para que la implementación y el caso de prueba utilicen exactamente la misma cadena.

La corrección deberá realizarse en el componente que resulte responsable después de acordar cuál es la nomenclatura oficial.

## Regresión

Después de aplicar la corrección se deberá:

1. Ejecutar nuevamente **TC-001 completo**.
2. Verificar que el paso 7 correspondiente a `health` resulte PASS.
3. Confirmar que el daemon continúe disponible después de las pruebas anteriores.
4. Revisar y ejecutar cualquier otro caso de prueba que valide la salida del comando `health`.
