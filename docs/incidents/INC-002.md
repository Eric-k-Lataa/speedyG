# INC-002 — Fallo de permisos al inicializar directorio de datos por defecto (`/var/lib/speedyg`)

## Identificación

* **Incidente:** INC-002
* **Requisitos relacionados:** RNF-03 (Sin privilegios de root), RF-16 (Configuración de directorio de datos)
* **Caso de prueba relacionado:** TC-014 (Compilación y ejecución en Linux estándar)
* **Severidad:** Alta
* **Fecha de detección:** 2026-11-01
* **Estado:** Abierto
* **Componente:** Daemon / Configuración (`src/config.rs`, `src/main.rs`)

## Síntomas

Al ejecutar el daemon `speedyG` directamente sin argumentos ni variables de entorno en un sistema Debian 13 (usuario estándar no privilegiado), el proceso falla al intentar crear el directorio de persistencia por defecto:

```text
ERROR speedyG: Error al crear directorio de datos /var/lib/speedyg: Permission denied (os error 13)
```

Esto impide la inicialización del daemon a menos que se ejecute con privilegios de `root`/`sudo` o se sobreescriba explícitamente el flag `--data-dir`.

## Evidencia

Ejecución del binario compilado por un usuario estándar en Debian 13:

```bash
$ cargo build
$ ./target/debug/speedyG
2026-11-01T00:15:00.000Z  INFO speedyG: Configuración cargada socket_path=/tmp/speedyg.sock queue_cap=3 max_current=3 grace_ms=5000 data_dir=/var/lib/speedyg
2026-11-01T00:15:00.001Z ERROR speedyG: Error al crear directorio de datos /var/lib/speedyg: Permission denied (os error 13)
```

Comprobación de permisos en el sistema operativo:

```bash
$ ls -ld /var/lib
drwxr-xr-x 40 root root 4096 Nov  1 00:00 /var/lib
```

El usuario sin privilegios carece de permisos de escritura en `/var/lib/`, lo que genera el error `EACCES` (`os error 13`).

## Hipótesis

1. **Hipótesis 1 (Confirmada):** El valor por defecto `DEFAULT_SPEEDYG_DATA_DIR` está fijado a `/var/lib/speedyg` en `src/config.rs`. En distribuciones Linux estándar, `/var/lib/` requiere privilegios de `root` para crear subdirectorios, violando el requisito de ejecución sin privilegios (RNF-03).
2. **Hipótesis 2 (Descartada):** El problema se debe a una mala configuración del usuario en Debian. Se descarta porque el sistema debe funcionar "out-of-the-box" para cualquier usuario no root según la especificación del proyecto.
3. **Hipótesis 3 (Descartada):** El entorno de CI falló por este motivo. Se descarta porque los scripts de verificación (`lib/common.sh`) crean un directorio temporal con `mktemp -d` en `/tmp/` y sobreescriben explícitamente `--data-dir` y `SPEEDYG_DATA_DIR`, enmascarando el error del valor por defecto.

## Causa

Inconsistencia entre el valor por defecto configurado en `src/config.rs` (`/var/lib/speedyg`) y el requisito **RNF-03 (Sin privilegios de root)**. Mientras que el socket por defecto (`DEFAULT_SPEEDYG_SOCKET`) utiliza `/tmp/speedyg.sock`, el directorio de datos apuntaba a una ruta de sistema que requiere privilegios administrativos.

## Corrección

1. Modificar `DEFAULT_SPEEDYG_DATA_DIR` en [`src/config.rs`](src/config.rs) para que apunte a una ubicación accesible sin privilegios de superusuario:
   ```rust
   pub const DEFAULT_SPEEDYG_DATA_DIR: &str = "/tmp/speedyg-data";
   ```
2. Asegurar que la documentación técnica y ejemplos (`config.example.toml`, `docs/technical-guide/README.md`) reflejen `/tmp/speedyg-data` como ruta por defecto de desarrollo/usuario, reservando `/var/lib/speedyg` únicamente para despliegues de sistema gestionados por paquetes o servicios dedicados.

## Regresión

Después de aplicar la corrección se deberá:

1. Compilar el proyecto desde un clon limpio con `cargo build`.
2. Ejecutar `./target/debug/speedyG` sin argumentos como usuario no root en Debian 13.
3. Verificar en `daemon.log` y stdout que:
   - `data_dir=/tmp/speedyg-data` se crea correctamente.
   - El daemon queda en estado activo y escuchando en el socket sin errores de permisos.
4. Ejecutar la suite de pruebas automatizadas (`verif/scripts/run-all.sh`) para asegurar que no se introdujeron regresiones en los casos que parametrizan `--data-dir`.

### Criterio de cierre

El incidente podrá cerrarse cuando:

* El daemon arranque de forma predeterminada sin requerir `sudo` ni flags adicionales en Debian 13.
* Se verifique la creación automática de `/tmp/speedyg-data` con permisos de usuario.
* El PR de corrección sea mergeado en la rama principal.
