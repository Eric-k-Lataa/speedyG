# TC-014 — Construcción reproducible desde clon limpio

## 1. Identificación

| Campo | Valor |
| ------- | ------- |
| **ID** | TC-014 |
| **Título** | Construcción reproducible desde clon limpio |
| **Prioridad** | Crítica |
| **Método** | Prueba / Inspección |
| **Tipo** | Construcción / Entrega |
| **Requisitos** | RNF-01, RNF-02, RNF-03, RNF-19, RNF-20 |
| **Estado** | PASS |

## 2. Objetivo

Verificar que la entrega se puede construir y verificar desde un clon limpio del repositorio, usando solo los comandos documentados en el README:

- **RNF-01.** Compilar y ejecutar en Linux declarado.
- **RNF-02.** Construcción reproducible desde clon limpio (toolchain fijado, `Cargo.lock` versionado, `--locked`).
- **RNF-03.** Sin privilegios de root.
- **RNF-19.** Compilar sin advertencias.
- **RNF-20.** Pruebas con un único comando documentado (`make verify`).

El script clona el repositorio en un directorio temporal y trabaja solo ahí. Por eso **solo se prueba lo que está commiteado**: los cambios sin commit no entran en el clon.

## 3. Precondiciones

1. Sistema Linux (Debian 13 en local; `ubuntu-latest` en CI) con `git`, `make`, `bash` y `build-essential`.
2. `rustup` instalado. El toolchain de `rust-toolchain.toml` se descarga solo la primera vez, por lo que se necesita acceso a red.
3. Usuario sin privilegios de root.
4. Los cambios a probar están commiteados (y, para una entrega, etiquetados).
5. El script tiene permisos de ejecución (`verif/scripts/TC-014.sh`).

## 4. Datos de prueba

| Dato | Valor |
| ---- | ----- |
| Referencia a probar | `HEAD` por defecto; `TC014_REF=<etiqueta o commit>` para fijar otra |
| Directorio del clon | `/tmp/speedyg-TC-014-clone-XXXXXX` (se borra al terminar) |
| Conservar el clon | `TC014_KEEP_CLONE=1` |

## 5. Procedimiento

```bash
# Candidato (tras crear la etiqueta)
TC014_REF=v1.0.0-rc1 bash verif/scripts/TC-014.sh

# Entrega final
TC014_REF=v1.0.0 bash verif/scripts/TC-014.sh
```

El script ejecuta, en este orden:

1. Comprueba SO (`uname -s`) y usuario (`id -u`).
2. `git clone` del repositorio y `checkout` de la referencia.
3. Comprueba que `rust-toolchain.toml` y `Cargo.lock` están versionados, y que no hay `target/` ni binarios ELF versionados.
4. Comprueba que `make verify` existe (`make -n verify`) y está documentado en el README.
5. `make build` y revisión de advertencias y binarios.
6. Registra el entorno del clon: distribución (`/etc/os-release`), arquitectura, `rustc` y `cargo` del clon, commit, hash de `Cargo.lock` y árbol de dependencias (`cargo tree --locked`).
7. `make fmt`, `make clippy` y `make test`.
8. Comprueba que `Cargo.lock` no cambió y que el árbol quedó limpio.

`make test` es el comando de pruebas dentro del clon. `make run-all` no se ejecuta desde TC-014: forma parte de `make verify`, y TC-014 está incluido en `run-all.sh`, por lo que llamarlo desde aquí sería recursivo.

## 6. Resultados esperados

### RNF-01 / RNF-03 — Entorno

- El sistema operativo es Linux.
- `id -u` es distinto de 0.

### RNF-02 — Reproducibilidad

- El clon se crea y la referencia solicitada existe.
- `rust-toolchain.toml` y `Cargo.lock` están versionados.
- No hay `target/` ni binarios ELF versionados.
- `make build` termina con éxito con `--locked`.
- Existen `target/release/speedyG` y `target/release/speedyg`.
- `Cargo.lock` no cambia durante el build.
- El árbol queda limpio tras construir.
- El `rustc` del clon corresponde al toolchain fijado en `rust-toolchain.toml`.
- Se registran la distribución y versión de Linux, la arquitectura, el commit del clon, el hash de `Cargo.lock` y las dependencias.

### RNF-19 — Sin advertencias

- `make build` no emite líneas `warning`.
- `make fmt` y `make clippy` (`-D warnings`) terminan con éxito.

### RNF-20 — Un único comando

- `make verify` está definido y documentado en el README.
- `make test` termina con éxito.

## 8. Criterios PASS/FAIL/BLOCKED

### PASS

Se cumplen **todos** los siguientes criterios:

1. Todas las comprobaciones de la sección 6 se registran como `[PASS]`.
2. El script termina con código 0.
3. El `run-id`, el commit y la etiqueta probados quedan en la evidencia.

### FAIL

1. Falla cualquier comprobación de la sección 6, por ejemplo `make build` con error, advertencias, `Cargo.lock` modificado o artefactos versionados.
2. El script se ejecuta como root.

### BLOCKED

- No hay red para descargar el toolchain o las dependencias.
- La referencia `TC014_REF` solicitada no existe en el repositorio local.
