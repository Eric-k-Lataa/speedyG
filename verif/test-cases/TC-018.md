## 2. Objetivo
Verificar que múltiples clientes puedan enviar trabajos simultáneamente sin generar identificadores duplicados, corrupción del Scheduler o pérdida de solicitudes.
## 3. Precondiciones
1. El proyecto debe compilar correctamente.
2. El daemon `speedyG` debe estar en ejecución.
3. El socket Unix debe estar disponible.
4. El cliente `speedyg` debe poder conectarse al daemon.
## 4. Datos de prueba
### Envíos concurrentes
```bash
for i in {1..20}; do
	cargo run --bin speedyg -- echo "job$i" &
done
wait
```
## 5. Procedimiento
1. Iniciar el daemon:
```bash
cargo run --bin speedyG
```
2. Ejecutar:
```bash
for i in {1..20}; do
	cargo run --bin speedyg -- echo "job$i" &
done
wait
```
3. Consultar estado:
```bash
cargo run --bin speedyg -- status
```
4. Verificar disponibilidad:
```bash
cargo run --bin speedyg -- health
```
## 6. Resultados esperados
### RF-26 — Solicitudes concurrentes
* Todas las solicitudes son aceptadas.
* Todos los trabajos son registrados correctamente.
### RF-27 — Operaciones concurrentes
* No existen identificadores duplicados.
* Cada trabajo recibe un identificador distinto.
### RNF-08 — Robustez
* El daemon continúa disponible después de la carga concurrente.
### RNF-27 — Consistencia
* El Scheduler mantiene integridad de los datos.

## 8. Criterios PASS/FAIL
### PASS
El caso se considera PASS cuando:
1. Se aceptan todas las solicitudes.
2. No existen IDs duplicados.
3. Todos los trabajos aparecen en el Scheduler.
4. El daemon continúa respondiendo correctamente.
### FAIL
El caso se considera FAIL cuando:
1. Existen IDs duplicados.
2. Se pierden solicitudes.
3. Existe corrupción del estado interno.
4. El daemon deja de estar disponible.
