# TC-017 — Cancelaciones concurrentes
## 1. Identificación
| Campo | Valor |
|--------|--------|
| **ID** | TC-017 |
| **Título** | Cancelaciones concurrentes |
| **Prioridad** | Crítica |
| **Método** | Prueba |
| **Tipo** | Funcional / Concurrencia |
| **Requisitos** | RF-26, RF-27, RNF-08, RNF-27 |
| **Estado** | PASS |
## 2. Objetivo
Verificar que múltiples clientes intenten cancelar simultáneamente el mismo trabajo sin producir estados contradictorios ni inconsistencias.
## 3. Precondiciones
1. El proyecto compila correctamente.
2. El daemon `speedyG` se encuentra en ejecución.
3. El socket Unix está disponible.
4. Existe un trabajo activo que pueda ser cancelado.
## 4. Datos de prueba
### 4.1 Trabajo prolongado
```text
sleep 50
```
### 4.2 Trabajo prolongado
```text
sleep 60
```
### 4.3 Trabajo prolongado
```text
sleep 70
```

## 5. Procedimiento
1. Iniciar el daemon:
```bash
cargo run --bin speedyG
```
2. Crear un trabajo:
```bash
cargo run --bin speedyg -- sleep 50
```
3. Obtener el ID generado.
4. Desde dos terminales distintas ejecutar simultáneamente:
```bash
cargo run --bin speedyg -- cancel <ID>
```
5. Consultar el estado final:
```bash
cargo run --bin speedyg -- status <ID>
```
## 6. Resultados esperados
### RF-26
- Una sola cancelación debe modificar el estado del trabajo.
- El sistema no debe producir transiciones inválidas.
### RF-27
- Ambos clientes reciben una respuesta comprensible.
### RNF-08
- El sistema mantiene consistencia bajo concurrencia.
### RNF-27
- El Scheduler conserva un único estado final válido.

## 8. Criterios PASS/FAIL
### PASS
1. Una única cancelación tiene éxito.
2. El trabajo termina en estado `Canceled`.
3. No aparecen estados contradictorios.
4. El servicio permanece operativo.
### FAIL
El trabajo presenta estados inconsistentes o múltiples estados finales.
